# Milestone 1: Project Scaffold + WASM Round-Trip — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the full Rust→WebAssembly→TypeScript→bun pipeline and prove it end-to-end with a byte-exact PDF round-trip (`PdfDocument.load(bytes)` then `doc.save()` returns the identical bytes), tested against the real fixtures.

**Architecture:** A Rust core crate (`crates/core`) compiled to WebAssembly with `wasm-bindgen`/`wasm-pack`. A thin TypeScript wrapper (`src/`) lazy-loads the generated WASM module and exposes an ergonomic `PdfDocument` class. This milestone implements only the trivial round-trip operation — no parsing yet — to lock in the build, packaging, and test loop that every later milestone depends on.

**Tech Stack:** Rust (cargo 1.94), `wasm-bindgen`, `wasm-pack` (`--target nodejs` for this milestone), TypeScript, `bun` (package manager + test runner).

---

## File Structure

This milestone creates the project skeleton. Each file has one responsibility:

- `package.json` — bun project metadata, scripts (`build:wasm`, `build`, `test`), `"type": "module"`.
- `tsconfig.json` — TypeScript config for the `src/` API (ESM, strict).
- `crates/core/Cargo.toml` — Rust crate manifest; `cdylib` for WASM output; `wasm-bindgen` dep.
- `crates/core/src/lib.rs` — Rust core; exposes `round_trip(bytes) -> bytes`.
- `src/wasm.ts` — internal: loads the generated WASM pkg, single source of the binding import.
- `src/index.ts` — public API: the `PdfDocument` class (`load`, `save`).
- `tests/roundtrip.test.ts` — bun test proving byte-exact round-trip on a real fixture.
- `pkg/` — generated by `wasm-pack` (already gitignored).

> Note: This milestone uses `wasm-pack --target nodejs` so tests run under `bun`/Node. The browser
> build target is added in Milestone 7 (browser parity). Do not add it now (YAGNI).

- [ ] **Step 1: Write the failing test in `tests/roundtrip.test.ts`**

```ts
import { test, expect } from "bun:test";
import { readFileSync } from "node:fs";
import { PdfDocument } from "../src/index.ts";

const FIXTURE =
  "tests/fixtures/Asistencia al Viajero/Formulario asistencia al viajero 1.pdf";

test("load then save returns byte-identical PDF", async () => {
  const original = new Uint8Array(readFileSync(FIXTURE));
  const doc = await PdfDocument.load(original);
  const out = await doc.save();
  expect(out).toBeInstanceOf(Uint8Array);
  expect(Buffer.from(out).equals(Buffer.from(original))).toBe(true);
});

test("load accepts an ArrayBuffer", async () => {
  const original = new Uint8Array(readFileSync(FIXTURE));
  const doc = await PdfDocument.load(original.buffer.slice(0));
  const out = await doc.save();
  expect(out.length).toBe(original.length);
});
```

- [ ] **Step 2: Run the test to verify it fails**

Run: `bun test tests/roundtrip.test.ts`
Expected: FAIL — cannot resolve `../src/index.ts` / `PdfDocument` is not defined.

- [ ] **Step 3: Implement `src/index.ts`**

```ts
import { roundTrip } from "./wasm.ts";

/**
 * A loaded PDF document. In Milestone 1 it simply holds the original bytes and
 * round-trips them through the Rust/WASM core. Later milestones add a parsed
 * document model and form operations.
 */
export class PdfDocument {
  /** @internal */
  private constructor(private readonly bytes: Uint8Array) {}

  /**
   * Load a PDF from bytes. Async because later milestones (and the browser build)
   * initialize the WASM module asynchronously; callers should always `await`.
   */
  static async load(input: Uint8Array | ArrayBuffer): Promise<PdfDocument> {
    const bytes = input instanceof Uint8Array ? input : new Uint8Array(input);
    return new PdfDocument(bytes);
  }

  /** Serialize the document back to PDF bytes. */
  async save(): Promise<Uint8Array> {
    return roundTrip(this.bytes);
  }
}
```

Run: `bun test tests/roundtrip.test.ts`
Expected: PASS — both tests green.
